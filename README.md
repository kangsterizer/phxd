# phxd
**phxd (Python hxd)** is a fully functional [**Hotline**](https://en.wikipedia.org/wiki/Hotline_Communications) pure **Python** server written with **Twisted**, originally written by **Vertigo** (avaraline.net) and later extended with hybrid **IRC support** by [**kang**](https://github.com/kangsterizer). The **IRC support** allows connecting to phxd using an **IRC client** and maps several **HLX** (Hotline) functions, like **public chat**, **private messages** and more. A **tracker client** functionality to register a **phxd** server instance with a (**passwordless**, public) **Hotline tracker** server was then later added.

# Dependencies
* **phxd** runs on **Python 3** (tested with Python 3.12).
* **phxd** is **Twisted** based. **PyYAML** is only needed to read a `phxd.yaml` configuration file (see below). Both can be installed via pip:
```
pip install -r requirements.txt
```

# Configuration

## Configuration attributes
**phxd**'s default configuration is stored in the config.py Python file. The recommended way to change it is a **YAML file** that overrides any of those settings: **phxd** reads `phxd.yaml` next to config.py at startup, or the file named by the **PHXD_CONFIG** environment variable. Settings use the config.py names in lower case:

```yaml
server_name: "My Hotline server"
server_description: "Yet another phxd server instance"
tracker_list:
  - tracker.preterhuman.net:5499
  - hotline.ubersoft.org          # the port defaults to 5499
log_level: INFO
```

A commented example is supplied in `phxd.yaml.example`. Unknown settings or values of the wrong type stop the server with an error message rather than being ignored. Settings derived from another one follow it: changing **"db\_file\_basepath"** also moves the database files and **"LOG\_FILE"** unless they are set explicitly.

The configuration can also be altered directly inside config.py (advanced users) or via a supplied interactive tool. Settings in `phxd.yaml` take precedence over config.py.

The program offers two methods of storing server related data (accounts, news, etc.): **"MySQL"** and **"Text"**.
* **"MySQL"** allows connecting to a mysql database instance with user/pass specified in the config.py file, and will use or create a new config.py "DB\_NAME" database to store **phxd** data. Note that storing **phxd** data using **"MySQL"** has not been tested recently.
* **"Text"** database will create a few `db_*.txt` files and directories containing the data generated by running **phxd** such as accounts data, banlist, news etc.

**phxd** always logs its internal events to standard output (so they show up in `docker logs` when running in Docker). If **"ENABLE\_FILE\_LOG"** is set to **True**, they are also written to the **"LOG\_FILE"** path, rotating logfiles every **"LOG\_MAX\_SIZE\_MBYTES"**, keeping a maximum of **"MAX\_LOG\_FILES"**. **"LOG\_LEVEL"** (default **INFO**) sets the minimum level logged; **DEBUG** adds hex dumps of every packet and is meant for troubleshooting only.

Connections whose client vanished without closing them (network drop, sleep, NAT timeout) are detected with TCP keepalive and closed within about two minutes, instead of the user staying listed for 15 minutes or more; see the **"TCP\_KEEPALIVE\_\*"** and **"TCP\_USER\_TIMEOUT"** settings.

The **"SERVER\_NAME"** and **"SERVER\_DESCRIPTION"** attributes will be used to advertise the server to Hotline tracker servers.
By default, the **phxd** instance will not be listed on any trackers. This can be changed with the **"TRACKER\_LIST"** setting, a list of tracker hostnames (or IP addresses) and ports. The Hotline server default port for advertising servers is **5499**, this differs to the port used by clients to list servers. The following configuration will get your server listed on the (currently) most active Hotline trackers running:

```yaml
# phxd.yaml
tracker_list:
  - tracker.preterhuman.net:5499
  - hotline.duckdns.org:5499
  - tracked.stickytack.com:5499
  - tracked.nailbat.com:5499
  - hotline.ubersoft.org:5499
```

or equivalently in config.py:

```
TRACKER_LIST=[("tracker.preterhuman.net", 5499),
              ("hotline.duckdns.org", 5499),
              ("tracked.stickytack.com", 5499),
              ("tracked.nailbat.com", 5499),
              ("hotline.ubersoft.org", 5499)]
```

## First time configuration
Before running **phxd**, configure it with a `phxd.yaml` file (see above), by editing the config.py file directly, or by running the configure_phxd.py tool interactively which will prompt you for important configuration options and rewrite the config.py file itself. Pay particular attention to the **"DB\_TYPE"**, **"SERVER\_NAME"** and **"SERVER\_DESCRIPTION"** settings.
**IMPORTANT NOTE**: If you use a **"DB\_TYPE"** of **"Text"** (the default) and are not using Docker, you ***must*** run the configurator tool with no arguments before the first launch: `$ ./configure_phxd.py` to generate the text database base files (the Docker image does this when it is built).

* Interactive configuration
The interactive tool provides an easy way to configure **phxd**'s most common configuration options. **phxd** should be configured before its first launch, by using the "configure_phxd.py" script as follow:
```
$ ./configure_phxd.py -i
```
The configurator script will prompt you with several configuration attributes in the following form `ATTRIBUTE_NAME=<default value> [Legal value/Legal value]`. If you wish to leave a specific attribute as default, press the "Enter" key. If you wish to change a particular attribute, enter the new value and press Enter, as shown in the following example:
```
$ ./configure_phxd.py -i
Choose a new value for each configuration attribute, and press enter or leave blank to leave the defaults in place.
If selecting 'DB_TYPE=Text' DB_USER, DB_PASS and DB_NAME don't apply.
DB_TYPE=Text [Text/MySQL]	MySQL
DB_USER=root	testuser
DB_PASS=	
DB_NAME=phxd	newservername
...
```
Once all the questions have been answered, the configurator program will exit, rewrite the **config.py** file according to the new attribute values given (or leaving all the options "as is" if none were changed), and generate the initial text database files (if a **"Text"** DB type was chosen).

* Editing **config.py** file directly
This is recommended for Users with some knowledge of Python, since the config.py file is actually a Python file that gets imported into the program. Attributes can be changed at will, including the ones the interactive tool doesn't ask about, such as the tracker list (see previous ["Configuration attributes"](#configuration-attributes) section). Once the attributes have been modified, make sure to run `$ ./configure_phxd.py` to generate the appropriate supporting files before running **phxd** for the first time.

# Installation
## Running phxd on a traditional operating system
There is no setup.py or other install package supplied with **phxd**. After installing the [dependencies](#dependencies), the program can be launched directly by simply invoking it with **Python 3** from its directory:
`$ python3 phxd`

Alternatively, a systemd service file could be created to run **phxd** on startup. Pay particular attention to the **"DB\_FILE\_\*"** attributes if you are using a **"DB\_TYPE"** of **"Text"** as **phxd** will create those database files by default in a **"textdb"** subdirectory of the directory it is started from. The **"DB\_FILE\_BASEPATH"** property can be altered to specify an absolute path instead; the database files and the **"LOG\_FILE"** follow it. The same applies to **"FILE\_ROOT"**, the directory of files shared with Hotline users (**"files"** by default).
## Running phxd as a Docker container
This is by far the easiest and most reliable method of installing **phxd**. A **Dockerfile** is supplied inside this repository to create a **Python 3** image that will run **phxd** as a container, using a docker Volume for **"Text"** database data and event logfiles. The configuration lives outside the image, in a `phxd.yaml` file mounted into the container, so changing it only requires a container restart, not an image rebuild.

1. Write your `phxd.yaml` as described in the earlier ["Configuration attributes"](#configuration-attributes) section, for example starting from `phxd.yaml.example`.
2. If you are using a **"DB\_TYPE"** of **"Text"** or have set **"ENABLE\_FILE\_LOG"** to **True**, create a Docker volume where **phxd** data will be stored:
```
# docker volume create <volumename>. We'll use "phxdvol" as a <volumename> in this example.
docker volume create phxdvol
```
**NOTE:** You can replace the Volume name as you see fit, or use an existing Volume if preferred.
3. Build the **phxd** Docker image:
```
# This must be ran from inside the "phxd" git repository directory
docker build -t phxd .
```
4. Run the **phxd** container:
```
docker run -d --name phxd \
  -v phxdvol:/app/textdb \
  -v $(pwd)/phxd.yaml:/app/phxd.yaml:ro \
  -v $(pwd)/files:/app/files \
  -p 5500:5500 -p 5501:5501 -p 6667:5500 \
  --restart=unless-stopped \
  phxd:latest
```

* The **"-v"** options map the data Volume, your configuration file and the directory of files shared with Hotline users (**"FILE\_ROOT"**) into the container. Without the files mount, uploaded files are lost when the container is recreated.
* The **"-d"** option tells Docker to detach from this container (i.e. run it in the background as a daemon)
* The **"-p"** options tell Docker which ports to listen to on the host OS and where to remap them inside the container.
    - We remap port **5500** which is the default Hotline port to the container port 5500 which **phxd** listens to, and port **5501** (**"server\_port"** + 1) which Hotline clients use for file transfers.
    - We also remap port **6667** to the container as IRC clients will by default use that port and **phxd** listens for both protocols on a single, shared port.
* The **"--restart=unless-stopped"** option will tell Docker to restart this container automatically on reboot or after a crash.
* The last positional argument **"phxd:latest"** tells Docker to use the latest version of the "**phxd**" image we built earlier.

**Before** running the command, make sure all options match your configuration if you have altered the defaults:

* **DO** replace the **"phxdvol"** name with the Volume name you chose earlier.
* **DO** replace **"textdb"** from the **"/app/textdb"** argument with the **"db\_file\_basepath"** setting if you have modified it.
* **DO** adjust the **"-p"** options to map the **"server\_port"** setting and the file transfer port (**"server\_port"** + 1) if you have changed it (it defaults to **5500**).
* **DO** change the **"--restart=unless-stopped"** option if you do **not** want **phxd** to **restart automatically** on reboot.

Once running, the server's log is available with `docker logs phxd` (add `-f` to follow it).

### IRC over TLS
**phxd** can accept encrypted IRC connections on a separate port, by convention **6697**. Set **"irc\_tls\_port"** and point **"irc\_tls\_cert"** / **"irc\_tls\_key"** at a PEM certificate chain and private key, for example from Let's Encrypt:
```yaml
# phxd.yaml
irc_tls_port: 6697
irc_tls_cert: /etc/letsencrypt/live/chat.example.org/fullchain.pem
irc_tls_key: /etc/letsencrypt/live/chat.example.org/privkey.pem
```
and mount the certificates read-only and publish the port when running the container:
```
docker run ... \
  -v /etc/letsencrypt:/etc/letsencrypt:ro \
  -p 6697:6697 \
  ... phxd:latest
```
Only TLS 1.2 and newer are accepted. The certificate files are reloaded automatically when they change, so certificate renewals don't need a restart (a renewal that fails to load is logged and the previous certificate keeps being used). If TLS is enabled but the certificate can't be loaded at startup, **phxd** exits with an error message. Configure your IRC client to use SSL/TLS on port 6697; you can stop publishing port 6667 to only allow encrypted IRC connections.

### Reconfiguring
Edit `phxd.yaml` and restart the container, as the configuration is only read on **phxd**'s startup:
```
docker restart phxd
```
If the file has an error, **phxd** exits with a message explaining it, visible with `docker logs phxd`.

Rebuilding the image is only needed to update **phxd** itself. Since all of **phxd**'s user data is stored in the Docker Volume and the files directory, and the configuration in `phxd.yaml`, it is safe to destroy the container, rebuild the image and run a new container with the same options: the server will restart in the same state and with the same logs.

# Usage
Once running, **phxd** can be connected to by pointing any Hotline or IRC client at its **"server\_port"** (5500 by default; the Docker example above also publishes it on the usual IRC port 6667), or an IRC client using TLS at **"irc\_tls\_port"**.
* **Hotline**
When using a Hotline client, you can connect to the server as "Guest" by using a username of "guest" and no password. Guest access is fairly limited, and this is only useful to test your server. You **will** need to login as "admin" using a default password of "adminpass" and immediately change the admin password to a pass of your choice, or delete the admin account (after creating another privileged account of course).
* **IRC**
When using an IRC client, you **must** log in, either as **"guest"** or as any other User (e.g. **"admin"**), in order to access any functionality of the server. Any of the following works:

* **NickServ**: `/msg NickServ IDENTIFY <password>` logs into the account named like your nick (matched case-insensitively), and `/msg NickServ IDENTIFY <login> <password>` into any account. This is what IRC clients' "NickServ password" setting sends automatically. `/ns` and `/nickserv` work too.
* **Server password**: set your client's server password to `<login>:<password>` to be logged in as soon as you connect.
* **loginserv**: `/msg loginserv <login> <password>`, or `/msg loginserv guest`.
* **Automatic guest login**: if you don't log in within **"IRC\_GUEST\_LOGIN\_DELAY"** seconds (default 5, 0 disables it), you are logged in as **guest**, provided a guest account exists.

Logins are confirmed, or refused with the reason, by a notice from NickServ. A failed login closes the connection.
**NOTE:** **phxd** doesn't support SASL, and plain IRC connections are unencrypted: your user and password are sent in cleartext unless you connect over TLS (see ["IRC over TLS"](#irc-over-tls)). Make sure to use a unique password for **phxd** to avoid password reuse with other services.

The server will **"force-join"** you to the **#public** channel. This channel actually corresponds to the **public chat** from the Hotline server. Any messages you type there will be visible to all other Hotline and IRC Users.
Hotline users appear as `<uid>_<nick>`, with characters IRC doesn't allow in nicks removed (an apostrophe becomes a backtick).
To issue a **private message**, simply call `/msg <targetnick> message contents` with the nick as listed in the channel (e.g. ``/msg 3_Cat`Killer hello``), like you would on a "normal" IRC server.

# Caveats
Not all standard IRC commands are supported, unsupported commands will be replied by **"421: Unknown command"**.
Issuing any other commands than **"NICK"**, **"USER"**, **"PASS"** or **"CAP"** before registering will be replied with **"421: Unknown command"** and will trigger a connection closure by the server. **phxd** supports no IRCv3 capabilities: **"CAP LS"** is answered with an empty list and capability requests are refused.

[**Limechat**](http://limechat.net/mac/) on Mac, [**irssi**](https://irssi.org/) and [**znc**](https://wiki.znc.in/ZNC) on Linux have been successfully used as IRC clients with **phxd** in the past.
